# 归流 GUILIU

[简体中文](README.md) | **日本語** | [English](README.en.md)

**銀行の通知、レシート、明細ファイルを信頼できる家計簿にまとめます。使うほど正確になり、手間も減っていきます。**

归流（GUILIU）は、自分のパソコン上で動く AI 家計簿・家計分析ツールです。名前は、プロジェクト全体を貫く「循環」から来ています。あなたが確認したことや修正したことはすべてシステムに戻り、次からそのまま使えるルールや記憶になります。

役割分担はシンプルです。**予測できない入力は AI が受け止め、決まった処理はローカルのコードが担います。** 形式がばらばらの銀行通知、さまざまなレシート、不揃いな店名、出どころの違う明細ファイルは大規模言語モデルが読み解き、ルールの検証・重複チェック・記帳・残高の計算はローカルのコードが決まったロジックで実行します。

ほとんどの agent はバックグラウンドで動きます。各工程に専用の agent がいて、バックエンドがその工程で直接呼び出します。新しい銀行の通知に合わせて解析ルールを書く、店舗をウェブで確かめてから分類する、メールやレシートから根拠を探して商品明細を補う、といった仕事です。判断に迷ったときだけ、あなたに確認を求めます。直接会話するのは分析 agent です。普段の言葉で質問すると、取引・商品明細・関連するメールやレシートとつながりをたどって一段ずつ調べ、結論・主要な数字・グラフで答えます。

![归流の概要：今期の支出、資産の変化、今月と先月の比較、取引件数のヒートマップ、カテゴリ別の要因](docs/screenshots/overview.png)

> スクリーンショットの口座・取引・会話はすべて架空のデモデータで、手元で隔離して動かした 0.1.0-rc.15 のものです。画面は中国語表示ですが、日本語と英語でも使えます。

## 使うほど正確に

- **解析ルール**：新しい銀行や通知の形式が現れると、モデルが解析ルールを書き、ローカルで検証を通ったものを銀行ごとに保存します。以降の同じ種類のメールはルールで解析し、モデルを呼びません。
- **分類の記憶**：分類結果はベクトルデータベースに保存され、同じ店舗が次に現れたときにそのまま使われます。「修正モード」で直すと、その店舗の過去の取引と記憶もまとめて直ります。
- **人が判断に加わる仕組み**：自信のない取引はあなたに確認を求め、その答えを保存するので、同じことを二度聞きません。
- **データの蓄積**：記録が増えるほど、深い検索で複数のメールやレシートを一つの注文にまとめられるようになり、分析もあなたのお金の使い方に近づきます。

## 明細の取り込み方

- **銀行の利用通知メール**：Gmail または NetEase 163 メール（同時接続可）を接続すると、归流が 1 分ごとに新着メールを読み取り、ルールと大規模言語モデルで店舗名・金額・通貨・日時を抽出し、分類と重複チェックを経て記帳します。認識ルールは送信元ごとに自動生成され、内蔵の銀行リストには依存しません。形式が変わったときは作り直します。
- **レシート・支払い画面のスクリーンショット**：接続したメールアドレスに送るだけです。既存の引き落としに対応する画像はその取引の商品明細として追加され、二重には記帳しません。新しい支出であれば単独で記帳します。
- **明細ファイル**：Alipay・WeChat Pay の明細や銀行の入出金明細（CSV / Excel）をまとめて取り込めます。書き込む前にプレビューで確認できます。
- **明細の補完（ADR）**：銀行の引き落としで何を買ったのか。归流はメールやレシートから根拠を探し、商品明細を元の取引の下に追加します。
- Gmail の接続方法（Google 認証とアプリ パスワード）を切り替えても、処理済みのメールは処理済みと認識され、もう一度処理されることはありません。Gmail が保存した認証情報を受け付けなくなったときは、サイドバーと設定画面で再接続を案内します。

## 各画面

### 概要

開くとまず家計のサマリーが表示されます：ひと言の結論、今期の支出・1 日平均・今日の支出・先月のエンゲル係数、直近 30 日の資産の変化、今月と先月の日別比較、1 年分の取引件数のヒートマップ、支出を増やした・減らしたカテゴリ。集計期間・口座・主要通貨（日本円 / 人民元）はいつでも変更できます。

### 分析

変化を先に説明し、根拠はそのあとに示します。今月これまでと先月の同じ期間を並べ、日別の推移・カテゴリ別の要因・店舗別の要因から、どこで多く使ったかを示します。その下に月ごとの支出履歴と影響の大きい取引が続きます。

![分析：今月と先月の比較、カテゴリ別・店舗別の要因](docs/screenshots/insights.png)

### 取引

すべての取引を 1 つの表で：店舗名で検索し、番号・カテゴリ・日付で絞り込み、金額や日時で並べ替えられます。カテゴリにはアイコンが付き、長い一覧もなめらかにスクロールします。取引を開くと日時・金額・口座・カテゴリと補完された商品明細が見られ、そのまま編集もできます。修正モードをオンにしてカテゴリを直すと、同じ店舗の過去の取引と分類の記憶もまとめて修正されます。

![取引](docs/screenshots/transactions.png)

![取引の詳細：カテゴリと補完された商品明細](docs/screenshots/deal.png)

### 資産

銀行・現金・電子マネー・クレジットカードなどの口座をまとめて管理します：純資産、総資産と負債、資産の推移、口座ごとの元の通貨での残高と換算額、資産の構成。日本円と人民元はその日のレートで換算します。収入の記録や残高の調整ができ、クレジットカードは「利用限度額＋現在の未払い残高」で管理し、毎月の自動返済も設定できます。

![資産と負債](docs/screenshots/assets.png)

### 明細の取り込み

Alipay・WeChat Pay の明細や銀行の入出金明細を入れ、記帳先の口座を選びます。まず認識結果が表示され、状態・収支・支払い方法・日付・キーワードで絞り込み、店舗名やカテゴリを 1 行ずつ直せます。チェックした行だけが書き込まれます。同じ明細を別の口座に取り込み直すと、取り込み済みの行は自動で飛ばします。

![明細の取り込み](docs/screenshots/import.png)

### 目標

貯蓄や投資の目標金額と毎月の積立額を決め、口座をひも付け、積立や引き出しを記録して、累計の進捗、実績と計画の見込み、達成予定日を確認できます。Agent に計画の下書きを作ってもらうこともでき、確認してから保存されます。

![目標：長期投資・緊急資金・旅行資金](docs/screenshots/goals.png)

### Agent との会話とキャンバス

「今月はなぜ先月より使ったのか」のように自然な言葉で質問すると、Agent が家計簿を調べ、結論・主要な数字・関連する取引で答えます。必要に応じて、左側のキャンバスに指標・日別の推移・カテゴリ別の比較・明細表を並べたグラフ付きレポートを作ります。連続した会話、会話履歴、Web 検索に対応し、好みも少しずつ覚えていきます。設定で登録した ID が、AI からの呼び名になります。

![Agent との会話とキャンバスのレポート](docs/screenshots/agent.png)

### Agent のお知らせ

Agent が自分で見つけたことがここに集まります。分析・異常・要確認の 3 種類で、それぞれ関連する取引とデータの期間が付きます。要確認のものは「確認済みにする」（取り消し可）、関連する取引を開く、会話で返信する、のいずれかで対応できます。

![Agent のお知らせ：確認待ちの項目](docs/screenshots/review.png)

### 自動タスク

定期的に知りたいことをひと言で書き、スケジュール（毎日・毎週・手動）を選ぶと、Agent が時間どおりに実行して結果を「Agent のお知らせ」に届けます。タスクごとに実行履歴が残り、いつでも一時停止やすぐの実行ができます。

![自動タスクと実行履歴](docs/screenshots/agent-tasks.png)

### 設定

カード形式の設定画面で、よく変える項目から順に並んでいます：プロフィール（アイコンと ID）、データの範囲、メール（Gmail / 163、接続が切れたときはワンクリックで再接続）、外観と表示、バージョンと更新、メールの一括読み込み（いつでも停止可）、実行設定。あまり使わない接続や開発者向けの項目は「詳細設定」にまとめています。

![設定](docs/screenshots/settings.png)

このほか、中国語・日本語・英語の 3 言語 UI、ライト / ダークテーマに対応し、損益の赤・緑の配色はワンクリックで入れ替えられます。

## 機能

- **明細の自動取り込み**：Gmail または NetEase 163 メール（同時接続可）の銀行利用通知を読み取り、ルールと大規模言語モデルで店舗名・金額・通貨・日時を抽出し、分類と重複チェックを経て記帳します。認識ルールは送信元ごとに自動生成され、内蔵の銀行リストには依存しません。
- **レシート・明細の取り込み**：メールで送ったレシートや支払い画面のスクリーンショットを認識して記帳します。Alipay・WeChat Pay の明細（CSV / Excel）の取り込みにも対応し、プレビューで確認・修正でき、重複の疑いがあるものは確認してから書き込みます。
- **明細の補完（ADR）**：銀行の引き落とし 1 件ごとにメールやレシートから根拠を探し、商品明細を元の取引の下に追加します。支出が二重に計上されることはありません。
- **レポート形式の概要**：ひと言サマリー、今月と先月の日別比較、カテゴリ別の要因、年間カレンダーのヒートマップ。日付・口座・主要通貨（日本円 / 人民元）で切り替えられます。
- **資産と口座**：銀行・現金・クレジット口座と、複数通貨を換算した純資産・残高の推移。
- **分析する Agent**：自然な言葉で質問すると、結論・主要な数字・関連する取引・グラフ付きレポートが返ってきます。連続した会話、Web 検索、好みのプロフィールに対応します。
- **目標・自動タスク・Agent からの提案**：貯蓄 / 投資プランと進捗、定期実行の自動タスク、Agent が見つけた気づきや確認事項。
- 中国語・日本語・英語の 3 言語 UI、ライト / ダークテーマ。

## データは手元に

- 3 つのサービスはローカルアドレスでのみ待ち受け、家計簿・ベクトルデータベース・会話履歴・認証情報・ログはすべてプログラムフォルダ内の `.runtime/` に保存されます。ブラウザからアクセスするにはこのパソコンとのペアリングが必要で、ペアリングはランチャーが自動で行います。
- メールは読み取るだけで、送信・削除・既読化は行いません。ダウンロード版の Gmail はアプリ パスワード（SSL IMAP）で接続します。自分で Google OAuth アプリを用意すれば、Google 認証（読み取り専用）も使えます。163 メールは IMAP 認証コードで接続します。
- 外部サービスを使う処理：メールの読み取り（Google / NetEase）、情報の抽出と対話（通義千問 / Qwen）、テキストのベクトル化（OpenAI）、Agent の Web 検索、為替レート（ExchangeRate-API、Frankfurter）、新しいバージョンの確認（GitHub）。関係するメールやレシートの内容は自分で設定したモデルサービスに送信され、利用料金は各サービス事業者から請求されます。
- オンライン更新の更新パッケージと更新情報は署名を確認し、切り替え前にデータを自動でバックアップし、新しいバージョンが起動しない場合は元のバージョンに自動で戻ります。
- 归流は 1 台のパソコンで 1 人が使うためのものです。サービスを LAN やインターネットに公開しないでください。

## ダウンロードと使い方

**[最新版をダウンロード](https://github.com/rhinoqvq/GuiLiu/releases/latest)**（Windows 10 / 11、64 ビット）

1. 上のページから `GUILIU-<バージョン>-win-x64.zip` をダウンロードします。ポータブル版には Python 3.13、Node 22 とすべての依存パッケージが含まれており、ほかに何もインストールする必要はありません。
2. 書き込み権限のあるフォルダ（デスクトップなど）にすべて展開し、`start_windows.cmd` をダブルクリックします。ランチャーが空いているポートを自動で選び、ブラウザを開きます。黒いウィンドウが归流本体なので、使っている間は閉じないでください。
3. 初回は画面の案内に従って初期設定を行います：API の設定と接続テスト → Gmail / 163 の接続 → メールのインデックス作成 → 銀行の送信元の識別 → 口座の確認 → レシートを送るメールアドレスの設定 → 完了。

必要なもの：

- 通義千問（Alibaba Cloud Model Studio）の API キーと OpenAI の API キー
- Gmail または NetEase 163 のメールアカウント。Gmail は 2 段階認証をオンにしてから 16 桁のアプリ パスワードを作成します。163 は IMAP をオンにして認証コードを取得します。初期設定の画面で手順を案内します。

展開したパッケージ内の `README.md` が使い方、`DEPLOYMENT.md` がデプロイと運用の詳細です（いずれも中国語）。

メールの自動同期・明細の補完・自動タスクは既定でオンになっており、初期設定が終わってから動き始めます。メールの自動同期は設定画面でオフにできます。新しいバージョンは「設定 → バージョンと更新」か、サイドバー左下の更新ボタンからワンクリックでインストールできます。

## iPhone のショートカットでスクリーンショットをすぐ送る

支払い完了画面、電子レシート、注文詳細を開いたまま iPhone の背面をダブルタップすると、今の画面をスクリーンショットして帰流が読むメールアドレスへそのまま送ります。帰流が画像を読み取って記帳します。設定は一度だけです。

**準備**

- 宛先：帰流に接続した Gmail または 163 のアドレス。
- 送信元：初期設定の「レシートの送信元」で入力したアドレス。帰流はこのアドレスから届いた画像だけを読み取るので、iPhone の「メール」App にこのアカウントを追加しておきます。あとで変える場合は「設定 → 実行設定」の「OCR メール検索条件」を `from:アドレス` の形で書き換えます。

**ショートカットを作る**

1. 「ショートカット」App を開き、右上の「+」で新規作成し、「帰流にスクショを送る」などの名前を付けます。
2. 「アクションを追加」から「スクリーンショットを撮る」を検索して追加します。
3. 続けて「メールを送信」を追加し、送る内容が前の「スクリーンショット」になっていることを確認します。宛先には帰流に接続したアドレスを入れ、件名は「帰流スクショ」など自由です。
4. 「メールを送信」の詳細を開き、「作成シートを表示」をオフにすると、編集画面を出さずにそのまま送信します。複数のメールアカウントがある場合は「差出人」でレシートの送信元を選びます。
5. 一度実行してみます。初回はメール送信を許可するか聞かれるので「常に許可」を選びます。

**起動方法**（どれか一つ）

- 背面タップ（iPhone 8 以降）：設定 → アクセシビリティ → タッチ → 背面タップ → ダブルタップ（またはトリプルタップ）で、このショートカットを選びます。
- アクションボタン（iPhone 15 Pro 以降）：設定 → アクションボタン → ショートカットで、このショートカットを選びます。
- ホーム画面やコントロールセンターに追加したり、Siri にショートカット名を話しかけたりしても起動できます。

**送ったあと**

帰流は新しいメールを読み取ると画像を認識します。既存の銀行引き落としに対応する場合はその明細に品目を補い、二重に記帳しません。新しい支出なら単独で記帳し、支出ではない画像はスキップします。メールの自動同期をオンにしておく必要があります。パソコンが起動していない間に送ったスクリーンショットは、次に帰流を起動したときに処理されます。

- 画面全体が送られます。起動する前に、送りたくない情報が映っていないか確認してください。
- 写真 App にある撮影済みのスクリーンショットを送りたい場合は、別のショートカットを作り、詳細で「共有シートに表示」をオンにして「メールを送信」だけを追加し、送る内容を「ショートカットの入力」にします。写真 App で画像を選び、共有 → このショートカットを選びます。

## リポジトリの構成

| パス | 内容 |
| --- | --- |
| `frontend/` | 素の HTML / CSS / JavaScript の画面と Node.js のローカルサーバー（静的ファイル、ローカルペアリング、同一オリジンのプロキシ）。ビルド手順も `npm install` も不要です |
| `backend/` | Python / FastAPI：メールの読み取り（Gmail API、IMAP）、日々の処理ループ、ルール抽出、明細の取り込み、家計簿と資産の計算、初期設定の流れ、オンライン更新。SQLite に保存します |
| `agent/` | Python / FastAPI：大規模言語モデル（通義千問）の呼び出し、Embedding（OpenAI）と LanceDB ベクトルデータベース、ツールの実行、レシートの認識、分類、明細の補完、計画、自動タスクと Agent のお知らせ |
| ルート | 統合ランチャー `run.py`（3 つのサービスの一括起動、空きポートの自動選択、ブラウザのペアリング、一括停止）、スモークテスト `smoke.py`、依存関係の一覧 `requirements.txt` と `constraints.txt`、デプロイガイド `DEPLOYMENT.md` |
| `release/` | パッケージのビルドスクリプト `build.py`・`portable.py`、ランチャー `launch.py`、実行環境の一覧 `RUNTIMES.json`、パッケージ内の説明 `README.package.md`。`release/windows/` は Windows の起動 / 停止 / インストール用スクリプト、`release/macos/` は手元で作る Apple シリコン用パッケージ（署名なし、配布はしていません）のインストーラーです |
| `docs/screenshots/` | このページのスクリーンショット |

3 つのサービスはそれぞれの認証情報で互いを認証し、ブラウザが長期の鍵を受け取ることはありません。

## ソースから実行

Python 3.13 と Node.js 22 以降が必要です。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py serve
```

ランチャーはフロントエンド・バックエンド・Agent を一度に起動し、空いているポートを自動で選び（既定は 3000 / 8001 / 8000。使用中なら次のポートに移ります）、ブラウザを開いてペアリングします。実行データは `.runtime/` に書き込まれるので、Git にコミットしないでください。デバッグ時は `--frontend-port`、`--backend-port`、`--agent-port` でポートを固定できます。Google 認証で「ウェブ アプリケーション」タイプのクライアントを使う場合、バックエンドのポートを Google Cloud コンソールに登録したリダイレクト URI と一致させる必要があります。ソースから実行している場合はオンライン更新できないので、Git で新しいバージョンを取得してください。
