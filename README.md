# 归流 GUILIU

**简体中文** | [日本語](README.ja.md) | [English](README.en.md)

**把银行通知、小票和账单文件整理成一本可信的账本，越用越准，越用越少需要你操心。**

归流是一个在你自己电脑上运行的 AI 记账与财务分析工具。名字来自贯穿整个项目的回环：你的每一次确认和修正都会流回系统，变成下次可以直接复用的规则和记忆。

它的分工是：**AI 负责兼容不确定的输入，本地代码负责确定的部分。** 格式各不相同的银行通知、各式各样的小票、不规范的店名、来源各异的账单文件，交给大模型去读懂；规则验证、查重、记账和余额计算，交给本地代码按确定的逻辑执行。

大部分 agent 都在后台工作。每个环节配了一个专门的 agent，由后端在对应环节直接调用：为新的银行通知写解析规则，联网核实商家后再分类，在邮件和小票里找证据补全商品明细。拿不准的时候，才把问题交给你确认。你能直接对话的是分析 agent：用自然语言提问，它会顺着账单、商品明细和关联的邮件、小票逐层去查，给出结论、关键数字和图表。

![归流总览：本期支出、资产变化、本月与上月对比、账单数量分布和分类驱动](docs/screenshots/overview.png)

> 截图中的账户、交易和对话都是虚构的演示数据，来自本机隔离运行的 0.1.0-rc.15。

## 越用越准

- **解析规则**：遇到新的银行或通知格式，模型写出解析规则，在本地验证通过后按银行保存；之后同类邮件直接用规则解析，不再调用模型。
- **分类记忆**：分类结果存进向量库，下次遇到同一商户直接复用；在「修正模式」下改正，同一商户的历史账单和记忆会一起改。
- **人在回路**：拿不准的交易交给你确认，确认结果会存下来，下次不用再问。
- **数据积累**：记录越多，深度检索越能把多封邮件和小票拼成完整的订单，分析也越贴近你的消费习惯。

## 账单怎么流进来

- **银行通知邮件**：连接 Gmail 或网易 163（可以同时连接），归流每分钟读取新邮件，用规则和大模型提取商户、金额、币种与时间，分类、查重后入账。识别规则按发件人自动生成，不依赖内置的银行列表；规则失效时会重新生成。
- **小票和支付截图**：发到已连接的邮箱即可。图片会被识别：对应已有扣款时补成那笔账单的商品明细，不会重复记账；是新消费时单独入账。
- **账单文件**：支付宝、微信账单和银行流水（CSV / Excel）可以批量导入，先预览再写入。
- **明细补全（ADR）**：一笔银行扣款买了哪些东西？归流在邮件和小票里找证据，把商品明细补到原账单下面。
- 换了邮箱连接方式（Google 授权和应用专用密码之间切换）后，以前处理过的邮件会被认出来，不会重新处理；Gmail 授权失效时，侧栏和设置页会提示重新连接。

## 每个页面

### 总览

一打开就是一份财务简报：一句话结论，本期支出、日均、今日消费和上月恩格尔指数，最近 30 天的资产变化，本月和上个月逐日对比，一年的账单数量分布（日历热力图），以及哪些分类让支出变多或变少。统计的日期范围、账户和主要货币（日元 / 人民币）可以随时调整。

### 洞察

先解释变化，再展开证据。本月至今和上月同期并排比较，逐日趋势、分类驱动和商户驱动告诉你钱多花在了哪里，下面是月度花销历史和影响最大的几笔交易。

![洞察页：本月和上个月的对比、分类驱动和商户驱动](docs/screenshots/insights.png)

### 交易

所有账单在一张表里：按商户搜索，按编号、分类和日期筛选，按金额或时间排序，分类带图标，长列表也能流畅滚动。打开一笔账单可以看到时间、金额、账户、分类和补全的商品明细，也可以直接编辑；开启「修正模式」后再改分类，同一商户的历史账单和分类记忆会一并修正。

![交易明细](docs/screenshots/transactions.png)

![账单详情：分类与补全的商品明细](docs/screenshots/deal.png)

### 资产

银行、现金、电子钱包、信用卡和其他账户放在一起：净资产、总资产与负债、资产随时间的变化、每个账户的原币余额和折算金额、资产构成。支持多币种（日元、人民币）按当日汇率折算；可以记录收入、校准余额；信用卡按「额度 + 当前欠款」管理，可以设置每月自动还款。

![资产与负债](docs/screenshots/assets.png)

### 导入账单

把支付宝、微信导出的账单或银行流水放进来，选好记到哪个账户。归流先给出识别结果：按状态、收支、付款方式、日期和关键词筛选，逐条修改商户和分类，勾选的才会写入。同一份账单换账户再导入时，已导入的会自动跳过。

![导入账单](docs/screenshots/import.png)

### 目标

为存款或投资设定目标金额和每月投入，关联账户，记一笔投入或取出，随时看累计进度、实际记录与计划预测，以及预计完成日期。Agent 可以先帮你拟一份计划草案，确认后才保存。

![目标：长期投资、应急备用金、旅行基金](docs/screenshots/goals.png)

### Agent 对话与画布

用自然语言提问，比如「这个月为什么花得比上个月多」。Agent 会查你的账本，给出结论、关键数字和相关账单；需要时在左侧画布生成图表报告：指标、每日趋势、分类对比和明细表。支持连续对话、历史会话、联网搜索，并逐步积累你的偏好；在设置里填的 ID 就是 AI 对你的称呼。

![Agent 对话与画布报告](docs/screenshots/agent.png)

### Agent 提示

Agent 主动发现的情况集中在这里，分为分析、异常和待确认三类，每条都附关联账单和数据期间。需要你确认的可以直接标记为已确认（可撤销）、打开关联账单，或者在对话中回复。

![Agent 提示：待确认的条目](docs/screenshots/review.png)

### 自动任务

用一句话描述你想定期了解的事情，选好周期（每天、每周或手动），Agent 会按时执行，结果发布到「Agent 提示」。每个任务都有执行记录，可以随时暂停或立即执行。

![自动任务与执行记录](docs/screenshots/agent-tasks.png)

### 设置

卡片式的设置页，按常用程度排列：个人资料（头像和 ID）、数据范围、邮箱连接（Gmail / 163，失效时可以一键重新连接）、外观与偏好、版本与更新、全量邮件加载（可随时停止）和运行配置，不常用的连接与开发者选项收在「高级选项」里。

![设置](docs/screenshots/settings.png)

此外：中文、日本語、English 三种界面语言，日间 / 夜间主题，盈亏红绿配色可以一键反转。

## 功能

- **账单自动归流**：读取 Gmail 或网易 163 中的银行消费通知（可以同时连接），用规则和大模型提取商户、金额、币种与时间，分类、查重后入账。识别规则按发件人自动生成，不依赖内置的银行列表。
- **小票与账单导入**：发到邮箱的小票或支付截图会被识别入账；支持导入支付宝、微信账单（CSV / Excel），先预览、可修改，疑似重复需确认后才写入。
- **明细补全（ADR）**：为一笔银行扣款在邮件和小票里找证据，把商品明细补到原账单下，不重复计入支出。
- **报告式总览**：一句话简报、本月与上月逐日对比、分类驱动、全年日历热力图，可按日期、账户和主要货币（日元 / 人民币）切换。
- **资产与账户**：银行、现金、信用账户，多币种折算的净资产和余额趋势。
- **会分析的 Agent**：用自然语言提问，得到结论、关键数字、相关账单和图表报告；支持连续对话、联网搜索和个人偏好画像。
- **目标、自动任务与 Agent 提示**：储蓄 / 投资计划与进度，按周期执行的自动任务，Agent 主动提出的发现与待确认问题。
- 中文、日本語、English 三种界面语言，日间 / 夜间主题。

## 数据留在本机

- 三个服务只监听本机地址，账本、向量库、对话记录、凭据和日志都保存在程序目录下的 `.runtime/`。浏览器需要与本机配对后才能访问，配对由启动器自动完成。
- 邮件只读取，不发送、不删除、不标记已读。下载版的 Gmail 使用应用专用密码（SSL IMAP）连接；如果你自己配置了 Google OAuth 应用，也可以用 Google 授权（只读权限）。163 使用 IMAP 授权码。
- 需要外部服务的环节：邮件读取（Google / 网易）、信息提取与对话（通义千问）、文本向量化（OpenAI）、Agent 联网搜索、汇率（ExchangeRate-API、Frankfurter）、检查新版本（GitHub）。相关邮件和小票内容会发给你自己配置的模型服务，调用费用由服务商收取。
- 在线更新的更新包和更新信息都经过签名校验，切换前自动备份数据，新版本启动失败会自动回到原来的版本。
- 归流面向本机单人使用，不要把服务暴露到局域网或公网。

## 下载使用

**[下载最新版本](https://github.com/rhinoqvq/GuiLiu/releases/latest)**（Windows 10 / 11，64 位）

1. 在上面的页面下载 `GUILIU-<版本>-win-x64.zip`。压缩包里已经包含 Python 3.13、Node 22 和全部依赖，解压就能用，不需要另外安装任何东西。
2. 完整解压到有写入权限的文件夹（如桌面），双击 `start_windows.cmd`。启动器会自动选择空闲端口并打开浏览器。黑色窗口就是归流本身，使用期间不要关闭。
3. 首次使用按页面完成初始化：配置并检测 API → 连接 Gmail / 163 → 建立邮件索引 → 识别银行来源 → 确认账户 → 设置票据发件邮箱 → 完成。

需要准备：

- 通义千问（阿里云百炼）API Key 和 OpenAI API Key；
- 一个 Gmail 或网易 163 邮箱。Gmail 需要先开启两步验证，再生成 16 位应用专用密码；163 需要开启 IMAP 并获取授权码。初始化页面有分步引导。

解压后包内的 `README.md` 是使用说明，部署和运维细节见 `DEPLOYMENT.md`。

邮件自动同步、明细补全和自动任务默认开启，完成初始化后才开始运行；邮件自动同步可以在设置页关闭。以后的新版本在「设置 → 版本与更新」或侧栏左下角的「新版本更新」里一键安装。

## 用 iPhone 快捷指令一键发送截图

付款后停在付款成功、电子小票或订单详情页面，轻点两下手机背面：iPhone 截下当前屏幕并直接发到归流读取的邮箱，归流识别后入账。只需要设置一次。

**准备**

- 收件地址：归流已连接的 Gmail 或 163 邮箱。
- 发件地址：初始化时「设置票据发件邮箱」一步填写的地址。归流只识别从这个地址发来的图片，所以 iPhone 自带的「邮件」App 里要登录这个邮箱。以后要换地址，在「设置 → 运行配置」里修改「OCR 邮件查询条件」（写法是 `from:地址`）。

**创建快捷指令**

1. 打开「快捷指令」App，点右上角的「+」新建快捷指令，起个名字，比如「发送截图到归流」。
2. 点「添加操作」，搜索并添加「截屏」。
3. 再搜索并添加「发送电子邮件」，确认发送的内容是上一步的「截屏」。「收件人」填归流已连接的邮箱，主题随意，比如「归流截图」。
4. 展开「发送电子邮件」的更多选项：关闭「显示编写表单」，邮件就会直接发出，不再弹出编辑界面；手机上有多个邮箱账户时，在「发件人」里选票据发件邮箱。
5. 运行一次试试。第一次发送时 iPhone 会询问是否允许这个快捷指令发送邮件，选「始终允许」。

**设置触发方式**（任选一种）

- 轻点背面（iPhone 8 及以后）：设置 → 辅助功能 → 触控 → 轻点背面 → 轻点两下（或轻点三下），选这个快捷指令。
- 操作按钮（iPhone 15 Pro 及以后）：设置 → 操作按钮 → 快捷指令，选这个快捷指令。
- 也可以把它加到主屏幕或控制中心，或者对 Siri 说出快捷指令的名字。

**发出之后**

归流读到新邮件后识别图片：对应已有的银行扣款时，补成那笔账单的商品明细，不会重复记账；是新的消费时单独入账；不是消费记录的图片会被跳过。这需要邮件自动同步开着；电脑没开时发出的截图，会在归流下次运行时处理。

- 发出去的是整个屏幕，触发前确认屏幕上没有不想发出去的内容。
- 想发相册里已经截好的图：再建一个快捷指令，在它的详细信息里打开「在共享表单中显示」，只添加「发送电子邮件」，发送内容选「快捷指令输入」。之后在相册里选中图片 → 共享 → 选这个快捷指令。

## 仓库结构

| 目录 | 内容 |
| --- | --- |
| `frontend/` | 原生 HTML / CSS / JavaScript 界面与 Node.js 本机服务（静态文件、本机配对、同源代理）。没有构建步骤，不需要 `npm install` |
| `backend/` | Python / FastAPI：邮件读取（Gmail API、IMAP）、日常处理循环、规则提取、账单导入、账本与资产计算、初始化流程、在线更新，SQLite 存储 |
| `agent/` | Python / FastAPI：大模型调用（通义千问）、Embedding（OpenAI）与 LanceDB 向量库、工具执行、小票识别、分类、明细补全、计划、自动任务与 Agent 提示 |
| 根目录 | 统一启动器 `run.py`（一次启动三端、自动选择空闲端口、配对浏览器、统一关闭）、冒烟测试 `smoke.py`、依赖清单 `requirements.txt` 和 `constraints.txt`、部署说明 `DEPLOYMENT.md` |
| `release/` | 下载包的打包脚本 `build.py`、`portable.py`，启动器 `launch.py`，运行环境清单 `RUNTIMES.json`，包内说明 `README.package.md`；`release/windows/` 是 Windows 启动 / 关闭 / 安装脚本，`release/macos/` 是 Apple 芯片本机包的安装脚本（未签名，不提供下载） |
| `docs/screenshots/` | 本页的截图 |

三个服务之间用各自的凭据互相认证，浏览器拿不到长期密钥。

## 从源码运行

需要 Python 3.13 和 Node.js 22 以上。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py serve
```

启动器会一次启动前端、后端和 Agent，自动选择空闲端口（默认 3000 / 8001 / 8000，被占用时顺延），并打开浏览器完成配对。运行数据写入 `.runtime/`，不要提交到 Git。调试时可以用 `--frontend-port`、`--backend-port`、`--agent-port` 固定端口；使用 Google 授权的“网页应用”类型客户端时，后端端口必须与 Google 控制台登记的回调地址一致。从源码运行时不支持在线更新，用 Git 拉取新版本即可。
